# Техническая документация: два блочных устройства ядра Linux

## 1. Модуль `ramioblk` (RAM IO Block Device)

### 1.1. Назначение

Модуль реализует виртуальное блочное устройство, данные которого хранятся в буфере, выделенном в оперативной памяти. Устройство не привязано к физическому оборудованию и предназначено для изучения подсистемы `blk-mq` (multi-queue) ядра Linux.

### 1.2. Архитектура

| Параметр | Значение |
|----------|----------|
| Тип устройства | RAM-диск |
| Ёмкость | 16 МБ (32768 секторов) |
| Размер сектора | 512 байт |

### 1.3. Интерфейсы

| Элемент | Значение |
|---------|----------|
| Имя устройства | `/dev/ramioblk` |
| Major number | динамически назначаемый |
| Операции | open, release, ioctl |

### 1.4. Реализация операций ввода-вывода

Используется интерфейс **blk-mq**:

- `ramio_mq_ops` — структура с callback `queue_rq`
- `ramio_queue_rq` — обработчик запросов:
  1. Проверка выхода за границы устройства
  2. Обход сегментов запроса через `rq_for_each_bvec`
  3. Отображение страниц пользовательского буфера через `bvec_kmap_local`
  4. Копирование данных `memcpy` между буфером и внутренним хранилищем `dev->data`
  5. Завершение запроса через `blk_mq_end_request`

### 1.5. Управление памятью

| Элемент | Способ выделения |
|---------|------------------|
| Хранилище данных | `vmalloc()` |
| Управляющая структура | `kzalloc()` |

### 1.6. Процедура загрузки (`ramio_init`)

1. Выделение памяти под управляющую структуру
2. Выделение буфера данных через `vmalloc`
3. Инициализация tag set для blk-mq
4. Регистрация блочного устройства (`register_blkdev`)
5. Выделение `gendisk` через `blk_mq_alloc_disk`
6. Настройка лимитов очереди
7. Установка ёмкости (`set_capacity`)
8. Добавление диска в систему (`add_disk`)

### 1.7. Процедура выгрузки (`ramio_exit`)

1. Удаление диска (`del_gendisk`)
2. Освобождение tag set (`blk_mq_free_tag_set`)
3. Освобождение буфера данных (`vfree`)
4. Освобождение `gendisk` (`put_disk`)
5. Освобождение управляющей структуры (`kfree`)

## 2. Модуль `obdblk` (Over Basic Device)

### 2.1. Назначение

Модуль реализует блочное устройство-прослойку, которое перенаправляет все запросы на базовое блочное устройство, указанное при загрузке. Ведётся статистика чтений и записей, доступная через sysfs.

### 2.2. Архитектура

| Параметр | Значение |
|----------|----------|
| Тип устройства | прослойка над базовым блочным устройством |
| Ёмкость | наследуется от базового устройства |
| Лимиты очереди | наследуются от базового устройства |

### 2.3. Параметры загрузки

| Параметр | Тип | Описание |
|----------|-----|----------|
| `base_device_name` | `charp` | Путь к базовому блочному устройству (обязательный) |

### 2.4. Интерфейсы

| Элемент | Значение |
|---------|----------|
| Имя устройства | `/dev/obdblk` |
| Major number | динамически назначаемый |
| Статистика | `/sys/devices/.../obd_statistics` |

### 2.5. Реализация операций ввода-вывода

Используется callback `.submit_bio` в `block_device_operations`.

Псевдокод обработчика:

    static void obd_submit_bio(struct bio *bio)
    {
        // 1. Обновление статистики
        // 2. Замена целевого устройства (bio_set_dev)
        // 3. Повторный вызов submit_bio
    }

### 2.6. Статистика (sysfs)

| Поле | Описание |
|------|----------|
| `bytes_read` | общее количество прочитанных байт |
| `bytes_written` | общее количество записанных байт |

Доступна через атрибут `obd_statistics` (только чтение).

### 2.7. Процедура загрузки (`obd_init`)

1. Проверка наличия параметра `base_device_name`
2. Выделение управляющей структуры
3. Открытие базового устройства (`bdev_file_open_by_path`)
4. Копирование `queue_limits` с базового устройства
5. Регистрация блочного устройства (`register_blkdev`)
6. Выделение `gendisk` через `blk_alloc_disk`
7. Установка ёмкости из базового устройства
8. Добавление диска (`add_disk`)
9. Создание sysfs-файла статистики

### 2.8. Процедура выгрузки (`obd_exit`)

1. Удаление sysfs-файла
2. Удаление диска (`del_gendisk`)
3. Освобождение `gendisk` (`put_disk`)
4. Отмена регистрации блочного устройства (`unregister_blkdev`)
5. Закрытие базового устройства (`fput`)
6. Освобождение управляющей структуры (`kfree`)

---

## 3. Известные ограничения

**obdblk:**
- Отсутствует эксклюзивная блокировка (claim) базового устройства — возможен параллельный доступ

**ramioblk:**
- Данные не сохраняются после выгрузки модуля
- Ёмкость фиксирована на этапе компиляции

## 4. Тестирование

Модули проходят следующие тесты (если для конкретного тест актуален):

| Тест | Описание |
|------|----------|
| Raw I/O integrity | запись и чтение строки, проверка целостности |
| Bulk transfer (ramio) | запись/чтение 10 МБ, сверка MD5 |
| Filesystem test | создание ext4, монтирование, запись файла |
| Statistics check (obd) | проверка наличия и корректности sysfs-статистики |
